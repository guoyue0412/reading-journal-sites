# 郭跃个人博客设计规格

## 1. 目标

建设一个以“写给自己，也与世界分享”为核心的个人博客，长期记录秋招、实习、论文阅读和个人感悟。网站既应保留个人写作的温度，也要让招聘方、同行和朋友快速理解郭跃的成长轨迹与研究兴趣。

首版必须满足：

- “安静编辑部”视觉方向：暖纸色、深墨色、朱红点缀，大留白，中文宋体与无衬线混排。
- 秋招、实习、论文、感悟四个模块独立组织，互不耦合。
- 所有模块能通过标签、时间、主题和显式关联互相索引。
- 论文笔记支持行内 LaTeX 与独立公式块。
- 阅读与编辑体验适配手机、平板和电脑。
- 内容以可移植的 Markdown 为核心，避免被单一编辑器锁定。

## 2. 信息架构

网站采用多路由结构：

- `/`：首页，展示个人介绍、四个模块入口、近期文章、论文阅读进度和跨模块关联。
- `/jobs`：秋招记录索引。
- `/internship`：实习日记索引。
- `/papers`：论文阅读索引，支持主题、年份、来源和阅读状态筛选。
- `/reflections`：个人感悟索引。
- `/search`：统一搜索与交叉索引页。
- `/post/[slug]`：统一文章阅读页，根据内容类型加载对应模块视图。
- `/editor`：响应式便携编辑区，用于创建、导入、预览和导出 Markdown 草稿。

顶栏始终提供首页、四模块和统一搜索入口。移动端收敛为可展开导航，保证触控目标、阅读宽度和公式不溢出。

## 3. 模块隔离

四个内容模块各自拥有独立目录、数据类型和展示配置：

- `content/jobs/`
- `content/internship/`
- `content/papers/`
- `content/reflections/`

模块只依赖共享的内容契约和 UI 基础组件，不直接读取其他模块内部文件。新增或调整某一模块时，不需要修改其他模块。

共享层只负责：

- 解析 Markdown 与 frontmatter。
- 生成统一索引。
- 解析标签、时间、人物、项目和显式关联。
- 提供搜索、筛选和相关推荐。
- 渲染通用正文、代码块和数学公式。

## 4. 内容契约与交叉索引

所有文章使用统一基础字段：

```yaml
title: 文章标题
slug: stable-slug
type: jobs | internship | papers | reflections
date: 2026-07-22
summary: 一句话摘要
tags: [VLA, 秋招]
related: [another-slug]
status: draft | published
```

论文模块额外支持：

```yaml
authors: [作者]
venue: arXiv
year: 2026
paper_url: https://example.com
reading_status: queued | reading | reviewed | reproduced
topics: [触觉, 灵巧手, VLA]
```

统一索引层在构建时汇总所有已发布内容，生成以下关系：

1. 显式关系：`related` 指向的文章优先展示。
2. 标签关系：跨模块共享标签自动互链。
3. 时间关系：同一阶段的秋招、实习和感悟可在时间线上相邻呈现。
4. 主题关系：论文 `topics` 与其他文章 `tags` 匹配时建立关联。

索引结果只保存文章摘要和引用，不复制正文，从而保持模块隔离。

## 5. LaTeX 与正文渲染

Markdown 正文支持：

- 行内公式：`$a^2+b^2=c^2$`
- 独立公式块：`$$ ... $$`
- 标题、列表、引用、表格、代码块和链接。

使用 KaTeX 渲染数学表达式。解析失败时保留原始公式文本并显示克制的提示，不能导致整篇文章白屏。公式容器在窄屏可横向滚动，但正文页面本身不产生横向滚动。

## 6. 便携编辑

首版编辑区采用响应式双模式：

- 手机：编辑与预览在两个标签间切换。
- 平板：可切换标签或使用紧凑双栏。
- 电脑：Markdown 编辑与实时预览双栏显示。

编辑器支持：

- 选择内容模块并自动生成对应 frontmatter 模板。
- Markdown 与 LaTeX 实时预览。
- 导入 `.md` 文件。
- 导出标准 Markdown 文件。
- 在当前设备保存本地草稿，防止意外刷新丢失。

首版不提供匿名在线发布、账户系统或跨设备云同步。正式文章仍以仓库中的 Markdown 文件发布，确保内容可版本控制、可迁移。后续若需要从任意设备直接发布，再增加认证与云端存储，不让该能力侵入四个内容模块。

## 7. 视觉与交互

- 背景：暖纸色 `#F3EEE4`。
- 主文字：深墨色 `#20201E`。
- 次级文字：灰褐 `#78736A`。
- 边界：`#C8C0B2`。
- 强调：朱红 `#B8422F`。
- 标题与文章正文优先使用中文宋体栈；导航、标签和元信息使用无衬线字体。
- 通过细分隔线、编号、日期和留白形成编辑部版式，不使用装饰性插画。
- Hover 只做轻微位移、下划线和颜色变化；触屏不依赖 hover 才能理解内容。
- 尊重 `prefers-reduced-motion`，键盘焦点始终可见。

## 8. 错误处理与空状态

- 某模块暂无内容时，展示该模块的用途和如何添加第一篇文章。
- 搜索无结果时保留筛选条件，并提供清除条件入口。
- 无效关联只在构建期记录警告，不阻断其他内容展示。
- Markdown 或公式局部解析失败时降级显示原文。
- 本地草稿读写失败时提示用户立即导出 Markdown。

## 9. 验证标准

- 生产构建成功。
- 四个模块可独立访问，任一模块的数据变化不要求修改其他模块。
- 统一搜索能命中标题、摘要、标签、论文主题和来源。
- 显式关联与自动标签关联至少各有一组示例可验证。
- 行内公式、独立公式与窄屏公式滚动正常。
- 320px 手机、768px 平板和 1440px 桌面布局无内容遮挡或页面横向溢出。
- 编辑区在三类屏幕宽度下都能导入、预览、本地保存和导出 Markdown。
- 基本键盘操作、可见焦点和语义化标签通过人工检查。

## 10. 首版范围外

- 评论、点赞、订阅、统计后台。
- 多人协作与复杂权限。
- 匿名在线写作与直接发布。
- 跨设备云草稿同步。
- 外部 CMS、Obsidian 或 GitHub 自动同步。

这些能力保留为后续扩展，不影响首版内容契约和模块边界。
