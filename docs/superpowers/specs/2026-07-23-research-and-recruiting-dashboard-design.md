# 郭跃个人博客：研究档案与进度看板融合设计

日期：2026-07-23  
状态：待用户审核

## 1. 目标

在保留现有纸张感、中文长文排版、Obsidian 写作、LaTeX、草稿隔离和跨模块索引的基础上，将博客升级为“研究档案 + 进度看板”：文章阅读保持安静克制，索引页则直观展示论文阅读方式和秋招阶段。

设计参考开源技术博客的成熟特征：Tailwind Next.js Starter Blog 的标签与搜索、AstroPaper 的克制和无障碍、Retypeset 的书籍式中文排版与 LaTeX、Fuwari 的响应式卡片与内容分类。只借鉴信息架构和交互原则，不复制其视觉资产或代码。

## 2. 核心原则

1. 论文不采用强制流水线。每篇论文独立声明实际使用的阅读方式。
2. 阅读方式可多选；执行状态只能单选，两者严格分离。
3. 秋招以岗位为独立档案，并用投递、笔试、面试三个阶段组织内容。
4. 首页只呈现关键数字和近期动态，不做厚重的后台仪表盘。
5. 手机端优先保证可读、可筛选、可编辑，桌面端提供更高的信息密度。
6. 所有新增字段必须经过构建期校验；错误笔记不得进入线上内容。

## 3. 信息架构

### 3.1 首页

首页依次展示：

1. 个人主张与当前关注方向。
2. 近期文章，覆盖四个现有模块。
3. 双进度区：论文阅读概览与秋招进展概览。
4. 最近论文笔记，明确显示阅读方式与执行状态。
5. 最近秋招动态，明确显示公司、岗位与当前阶段。
6. 今日感悟和跨模块关联文章。

论文概览显示待读、进行中、总结中、已完成、已归档的数量；秋招概览显示已投递、笔试中、面试中、Offer 和结束的数量。两者均可点击进入对应索引页。

### 3.2 论文索引

桌面端使用“阅读方式矩阵 + 论文列表”组合；移动端转为纵向论文卡片。

每篇论文显示：

- 标题、作者、会议、年份、主题；
- 阅读方式标记：粗读、细读、总结；
- 唯一执行状态；
- 阅读日期和关联文章。

筛选条件：阅读方式、执行状态、主题、会议、年份。阅读方式筛选采用“包含”语义，例如选择“细读”会返回所有包含细读方式的论文，无论它是否同时包含粗读或总结。

### 3.3 论文详情

详情页只渲染笔记中真实存在的章节。推荐章节为：

- `## 粗读记录`：研究问题、核心贡献、方法直觉、是否值得继续；
- `## 细读记录`：模型结构、关键公式、数据、实验、消融、图表与疑问；
- `## 阅读总结`：一句话结论、优缺点、关联工作、研究启发和可复用观点。

章节均为可选。页面顶部的阅读方式标记必须与正文实际章节保持一致；构建时发现不一致则报错并阻止发布。

### 3.4 秋招索引

秋招索引包含漏斗统计、阶段筛选和按更新时间排列的岗位档案。漏斗阶段为：

`投递 → 笔试 → 面试 → Offer / 结束`

每个岗位卡片显示公司、岗位、地点、投递日期、当前阶段、最近事件和下一步。手机端使用纵向阶段卡片，不使用需要横向滚动的看板。

### 3.5 秋招详情

单个公司与岗位使用独立文章，推荐章节为：

- `## 投递`：时间、渠道、JD 匹配、简历版本和状态变化；
- `## 笔试`：时间、平台、题型、完成情况、知识缺口和补强行动；
- `## 面试`：轮次、时间、问题、回答复盘、反馈和下一步；
- `## 最终复盘`：结果、关键得失和可复用经验。

投递、笔试、面试按实际经历填写，不要求所有章节存在。当前阶段是单选字段，页面状态由字段决定，不从章节标题猜测。

## 4. 内容模型

### 4.1 论文字段

保留现有公共字段和论文元数据，新增：

```yaml
reading_methods: [skim, deep, synthesis]
reading_status: in_progress
```

`reading_methods` 是不可重复的多选数组，可选值：

- `skim`：粗读；
- `deep`：细读；
- `synthesis`：总结。

`reading_status` 是单选，可选值：

- `queued`：待读；
- `in_progress`：阅读中；
- `synthesizing`：总结中；
- `completed`：已完成；
- `archived`：已归档。

只有 `queued` 状态允许 `reading_methods: []`，界面显示“尚未选择阅读方式”。其他状态必须至少选择一种阅读方式。这样未开始的论文不会伪造阅读记录，已经开始的论文则一定能回答“以什么方式阅读”。

兼容规则：现有论文的旧状态在迁移时映射为新状态，并补充符合正文的 `reading_methods`；迁移完成后不再接受旧枚举。

### 4.2 秋招字段

在公共字段外新增：

```yaml
company: 公司名
role: 岗位名
location: 城市
application_stage: interview
applied_at: 2026-07-23
next_action: 准备二面项目复盘
```

`application_stage` 是单选，可选值：

- `applied`：已投递；
- `written_test`：笔试；
- `interview`：面试；
- `offer`：Offer；
- `closed`：结束。

`company`、`role`、`application_stage` 为必填；其余字段可选。若存在 `applied_at`，必须为有效的 `YYYY-MM-DD` 日期。

## 5. Obsidian 写作体验

更新 `博客/模板/论文阅读.md` 与新增 `博客/模板/秋招进展.md`。模板使用中文提示，但 frontmatter 使用稳定英文枚举。手机、平板、电脑均可直接复制模板写作。

同步器保持四栏目隔离，继续转换双链和附件。新增字段原样同步，并由内容生成器统一校验。`status: draft` 的文章会接受完整校验，但不会进入网站索引。

## 6. 页面组件边界

- `ProgressOverview`：只负责首页两组统计及跳转。
- `PaperMethodBadges`：只负责论文阅读方式标记，可在首页、索引和详情复用。
- `PaperFilters`：只负责论文筛选状态与筛选结果。
- `PaperIndex`：组合矩阵、筛选器和论文列表。
- `RecruitingFunnel`：只负责秋招阶段统计。
- `RecruitingIndex`：组合漏斗、筛选器和岗位卡片。
- 内容查询层负责统计和筛选，不在页面组件中重复推导。

组件通过已验证的 `ContentEntry` 类型通信，不直接读取 Markdown 或 Obsidian 文件。

## 7. 响应式与无障碍

- 桌面论文矩阵允许高密度对比，但保留清晰表头和行焦点。
- 小屏幕使用纵向卡片展示同样的信息，不依赖横向滚动。
- 状态不能只靠颜色表达，必须同时显示中文文字或符号。
- 所有筛选控件具备可见标签、键盘焦点和至少 44px 的触控高度。
- 尊重系统减少动态效果设置，不添加影响阅读的转场。

## 8. 错误处理

- 未知阅读方式、未知执行状态、重复阅读方式：构建失败并指出文件与字段。
- 非待读论文声明了某阅读方式但缺少对应章节：构建失败。
- 正文包含对应章节但 frontmatter 未声明：构建失败。
- 秋招缺少公司、岗位或阶段：构建失败。
- 无效日期：构建失败。
- 关联草稿、失效关联、重复 slug：沿用现有隔离和诊断规则。
- 单个错误不得产生部分更新的线上索引。

## 9. 测试与验收

### 内容模型

- 多种合法阅读方式组合均可生成；重复或未知值失败；空数组只允许用于待读论文。
- 执行状态只能为一个合法枚举。
- 阅读方式与正文章节双向一致。
- 旧论文迁移后内容数量和关联关系不丢失。
- 秋招必填字段、阶段和日期得到校验。

### 查询与界面

- 首页统计与实际已发布内容一致，草稿不计入。
- 论文可按阅读方式、状态、主题、会议和年份筛选。
- 秋招可按阶段筛选，漏斗数量准确。
- 桌面矩阵和移动卡片表达相同数据。
- 无结果状态提供清除筛选入口。

### 回归

- LaTeX、GFM 表格、代码块、Obsidian 双链和附件继续工作。
- 四个内容模块、全文搜索、404、跨模块索引和本地编辑器继续工作。
- 完整测试、代码检查和生产构建通过后才保存并部署新版本。
