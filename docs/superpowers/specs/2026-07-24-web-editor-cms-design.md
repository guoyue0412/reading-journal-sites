# 郭跃博客网页写作台与发布系统设计

日期：2026-07-24
状态：已完成交互设计，等待书面规格确认

## 1. 目标

把现有只能生成 Markdown 的便携编辑器升级为真正的网页写作后台。用户可在手机、平板和电脑上新建、编辑、预览、保存与发布博客，并通过不同文本框填写内容，无需从空白 Markdown 开始设计文章结构。

系统继续支持论文阅读、秋招记录、实习日记和每日感悟四个相互隔离但可交叉索引的模块，并保留 LaTeX、Markdown 与 Obsidian 协作能力。

## 2. 已确认的产品决策

- 公开站点用于阅读；`/editor` 写作后台仅站点所有者登录后访问。
- 采用 A 方案“分区式写作台”：左侧章节导航，中间结构化表单，右侧实时预览。
- 编辑过程中自动保存草稿；只有明确点击“发布”才更新公开正文。
- 已发布文章再次编辑时，先形成新的草稿版本，不直接覆盖公开版本。
- 网站是发布源；Markdown 支持双向导入导出，以便继续与 Obsidian 协作。
- 文章、文章组件、常用模块模板和发布版本分别持久化。
- 用户可以给当前文章新增组件，也可以把组件保存为同类文章的常用模块。

## 3. 权限与安全

### 3.1 阅读权限

已发布文章、模块索引、搜索与交叉引用对公开读者可见。草稿、历史编辑版本、常用模块和写作后台不出现在公开数据中。

### 3.2 编辑权限

写作后台使用平台提供的 ChatGPT 登录身份。页面渲染和所有写操作均在服务端校验身份；前端隐藏按钮不作为权限边界。所有者邮箱通过托管环境变量 `BLOG_OWNER_EMAIL` 配置，仅匹配该邮箱的登录用户能够创建、修改、发布、撤回、导入或删除内容。

未登录访问 `/editor` 时进入平台登录流程。已登录但不在所有者允许范围内时返回无权限状态，不泄露草稿内容。

## 4. 写作台界面

### 4.1 整体布局

- 左侧：文章类型、标准章节、自定义组件、文章列表、常用模块管理和 Markdown 导出入口。
- 中间：当前章节对应的结构化字段与可编辑组件。
- 右侧：与公开文章一致的 Markdown、GFM 和 LaTeX 实时预览。
- 手机：左侧导航收进菜单，正文采用“填写 / 预览”标签页。
- 平板：保留章节导航与表单，预览按需切换。
- 电脑：三栏同时显示。

### 4.2 通用字段

四类文章都包含标题、slug、日期、摘要、标签、关联文章和发布状态。slug 默认从标题生成，允许用户修改，并在保存时检查唯一性。

### 4.3 论文阅读模板

固定元数据包括作者、会议或来源、年份、论文链接、主题、阅读日期、阅读方式多选和执行状态单选。

标准模块包括研究问题、粗读记录、细读记录和阅读总结。阅读方式仍遵守现有规则：粗读、细读和总结可多选，执行状态单选；已选择的阅读方式必须有对应内容模块。用户可新增创新点、相关论文、实验设计、局限性等组件。

### 4.4 秋招模板

固定元数据包括公司、岗位、地点、申请日期、当前阶段和下一步行动。标准模块包括投递、笔试、面试和最终复盘；当前阶段在投递、笔试、面试、Offer 和结束中单选。

### 4.5 实习日记与每日感悟

实习日记提供今日任务、解决的问题、学习收获和明日计划等初始模块。每日感悟以日期为唯一日索引，提供今日事件、感受、反思和一句话总结等初始模块。用户均可新增或移除非核心组件。

## 5. 可扩展组件

组件类型首期支持：

- 长文本：适合研究问题、创新点、复盘等段落。
- 短文本：适合结论、来源或一句话字段。
- 清单：适合贡献点、问题列表、待办和面试题。
- Markdown / LaTeX：支持富文本结构、代码块、表格与公式。
- 关联文章：搜索站内文章或填写外部论文链接，并显示引用卡片。

每个组件具有稳定 ID、名称、类型、内容、排序序号和模板来源。用户可以新增、重命名、排序、复制和删除组件。

“保存为常用模块”会复制组件定义到当前文章类型的模板库。以后新建同类文章时自动加载该模块；模板内容默认留空，不复制当前文章正文。常用模块可在独立管理界面中改名、调整默认顺序、停用或删除。修改模板不追溯改变既有文章。

## 6. 数据模型

使用平台 D1 保存结构化数据，逻辑表如下：

- `posts`：文章身份、类型、核心元数据、草稿版本号、公开状态和时间戳。
- `post_sections`：文章组件，包含组件类型、标题、内容、顺序和模板来源。
- `section_templates`：按文章类型保存的标准模块与用户常用模块。
- `post_revisions`：每次发布时保存可恢复的公开快照。
- `post_relations`：站内文章间的显式关联与关系类型。

结构化元数据用于搜索、论文阅读矩阵、秋招进展漏斗、近期文章和跨模块索引。文章正文按组件顺序渲染；公开查询只读取已发布快照，避免未确认草稿泄露。

## 7. 保存与发布数据流

1. 用户选择文章类型并新建文章。
2. 系统加载该类型的固定字段、标准模块和启用的常用模块。
3. 用户填写时，前端短暂防抖后发送草稿保存请求。
4. 服务端验证所有者身份、字段规则、组件类型、slug 唯一性和客户端提交的草稿版本号，再原子保存文章与组件。
5. 预览使用当前草稿数据，不影响公开文章。
6. 用户点击发布后，服务端再次进行完整校验，创建不可变发布快照，并更新公开状态。
7. 首页、模块索引、搜索和交叉引用读取最新已发布快照。

已发布文章被继续编辑时，公开读者仍看到上一次发布快照，直至用户再次确认发布。

## 8. Markdown 与 Obsidian

### 8.1 导出

任意草稿或已发布文章均可导出为当前博客 schema 对齐的 Markdown：核心字段写入 YAML frontmatter，组件按顺序写成二级标题与正文。论文阅读方式、执行状态、秋招阶段和关联信息保留为现有字段名称。

### 8.2 导入

用户上传 Markdown 后，系统解析 frontmatter 与二级标题，将已知标题映射到标准模块，其余标题转换为自定义长文本或 Markdown / LaTeX 组件。导入先进入预览和字段校验，不自动发布。

无法识别的合法字段保留在导入报告中；格式错误会指出具体字段，不覆盖现有草稿。

### 8.3 现有内容兼容

现有仓库 Markdown 继续作为初始化与兼容来源。实施时提供一次性导入逻辑，把现有公开文章和草稿转换到新数据模型；原文件不在迁移中删除。迁移验证通过后，线上新增内容以数据库为准。

## 9. 可靠性与错误处理

- 自动保存显示“保存中、已保存、保存失败”状态。
- 网络失败时保留设备端临时草稿，恢复连接后允许重试；临时草稿不是权威发布源。
- 服务端使用事务或批处理保证文章与组件不会只保存一半。
- 发布前校验必要字段、日期、URL、论文阅读方式与章节一致性、秋招阶段以及关联文章有效性。
- slug 冲突、无权限、解析失败和版本冲突提供明确提示。不同设备同时编辑导致版本冲突时，不静默覆盖较新的草稿，而是保留本机内容并提示重新加载或另存副本。
- 删除文章或常用模块前二次确认；删除常用模块不删除既有文章组件。
- 发布版本可用于恢复公开正文，但首期不提供复杂的逐字差异编辑器。

## 10. 测试与验收

### 10.1 自动化测试

- 数据模型迁移与约束测试。
- 所有者授权、未登录和越权写入测试。
- 四类文章创建、自动保存、再次编辑与发布测试。
- 五类组件的新增、排序、复制、删除和常用模板复用测试。
- Markdown 导入导出往返测试，覆盖 LaTeX、表格、代码块与中文标题。
- 草稿不进入公开首页、搜索、模块索引和关联结果的测试。
- 论文阅读方式与章节、秋招阶段及每日感悟日期规则测试。
- 发布快照和版本恢复测试。

### 10.2 响应式验收

在手机、平板和电脑宽度验证表单可填写、控件触摸区域足够、侧栏不遮挡、预览可切换、长公式和表格可横向滚动。键盘用户可完成新增组件、排序替代操作、保存、预览和发布。

### 10.3 完成标准

- 用户能只通过网页完成一篇新博客从创建到公开发布的全过程。
- 用户能给当前文章新增“创新点”等组件并保存为常用模块。
- 新建同类文章会自动出现启用的常用模块。
- 已发布文章的未确认修改不会出现在公开站点。
- Markdown 可无内容丢失地导出并重新导入关键格式。
- 公开索引、论文矩阵、秋招漏斗和跨模块关联继续正常工作。

## 11. 首期不包含

- 多作者协作与评论审批。
- 图片、视频等大文件上传管理；文章仍可引用已有网络图片。
- 外部 OAuth、公开注册和角色管理。
- 自动把线上文章写入本机 iCloud Obsidian 目录。
- 类似 Notion 的任意嵌套画布和实时多人协同。

这些能力不会阻碍未来扩展；首期优先保证单人写作、结构化组件、可靠草稿、明确发布和 Markdown 往返。
