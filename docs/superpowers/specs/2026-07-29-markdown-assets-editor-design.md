# 全模块 Markdown 编辑与图片上传设计

## 1. 目标

网站编辑器中的每一个“内容模块”统一为 Markdown 文档片段。用户无需在长文本、短文本、清单、关联和 Markdown 等输入方式之间切换；所有模块都使用同一种编辑体验，并支持：

- GitHub Flavored Markdown；
- 行内与块级 LaTeX；
- 表格、代码块、引用和任务清单；
- Markdown 图片；
- 从剪贴板粘贴图片和从本地选择图片；
- 文章关联语法；
- 实时预览、自动保存、刷新恢复、Markdown 导入导出和发布。

文章级结构化信息继续使用表单：标题、slug、日期、摘要、标签、论文元数据、阅读状态、秋招阶段等不改成 Markdown。这些字段需要可靠筛选和索引，不属于文章正文。

## 2. 核心内容模型

### 2.1 模块边界

每个模块仍然保留：

- `id`：稳定身份；
- `title`：模块标题；
- `standardKey`：发布校验使用的标准组件标识，例如 `reading-summary`；
- `position`：模块顺序；
- `content`：唯一的 Markdown 正文。

编辑器不再根据 `long_text`、`short_text`、`checklist`、`relation` 显示不同输入控件。新建模块的规范类型统一为 `markdown`。现有 `kind` 字段暂时保留用于兼容读取，写回时规范化为 `markdown`，避免一次性破坏数据库和旧文章。

模块内容不包含 YAML frontmatter，也不包含自身的 `## 标题`。标题由模块标题字段管理；导出整篇文章时再组合为：

```md
## 阅读总结

这里是 Markdown 内容。
```

### 2.2 特殊语法

- 任务清单：`- [ ] 待完成`、`- [x] 已完成`。
- 文章关联：`[[slug]]` 或 `[[slug|显示标题]]`。
- 图片：`![替代文字](/media/<asset-id>/<safe-name>)`。
- 行内公式：`$E=mc^2$`。
- 块级公式：

```md
$$
\mathcal{L}=\sum_i \|y_i-\hat y_i\|^2
$$
```

关联索引由保存服务从 Markdown 中解析 `[[...]]` 后生成，`relationSlugs` 只作为派生兼容字段，不再由独立复选框编辑。未知 slug 在编辑器中显示警告，但不阻止保存；发布时阻止无效关联，避免生成断链。

## 3. 编辑器体验

### 3.1 统一 Markdown 输入

每个模块显示：

- 可编辑模块标题；
- Markdown 工具栏；
- 等宽字体文本区；
- 上传状态和错误提示；
- 模块级预览切换；
- 复制、排序和删除操作。

工具栏只提供高频操作：标题、粗体、链接、图片、公式、代码、任务清单和文章关联。工具栏操作在当前光标或选区插入语法，不抢走输入焦点。

右侧整篇文章预览继续使用 `react-markdown + remark-gfm + remark-math + rehype-katex`，保证编辑器预览与发布文章使用同一渲染规则。

### 3.2 图片粘贴

当 Markdown 文本区获得焦点后粘贴剪贴板：

1. 如果剪贴板包含图片，阻止浏览器将其作为二进制内容直接插入。
2. 在本地创建临时预览，不把 `blob:` URL 或上传占位符写入持久草稿。
3. 上传成功后，在粘贴时的光标位置插入最终 Markdown 图片语法。
4. 插入后进入现有自动保存队列。
5. 如果上传失败，正文保持原状，临时预览移除，并在当前模块显示可重试错误。

一次粘贴包含多张图片时按剪贴板顺序上传和插入。粘贴同时包含文字与图片时，保留文字顺序；第一版以浏览器提供的 ClipboardItem 顺序为准。

### 3.3 本地选择

工具栏的“图片”按钮打开系统文件选择器，支持多选。手机端可从相册或相机选择；上传结果同样在当前光标位置插入 Markdown。

## 4. 图片存储与访问

### 4.1 存储职责

- R2 逻辑绑定：`BLOG_ASSETS`，保存图片字节。
- D1：新增 `blog_assets` 表，保存图片元数据、所属文章和公开状态。
- 浏览器存储：仅保存上传中的临时 UI，不作为图片或文章的权威来源。

`.openai/hosting.json` 的 `r2` 从 `null` 改为 `BLOG_ASSETS`。

### 4.2 D1 元数据

`blog_assets` 表包含：

- `id`：随机 UUID；
- `post_id`：上传时所在草稿；
- `object_key`：R2 对象键；
- `original_name` 与 `safe_name`；
- `content_type`；
- `size_bytes`；
- `sha256`：重复图片检测；
- `visibility`：`draft` 或 `published`；
- `created_at`、`updated_at`。

`post_id + sha256` 建唯一索引。同一文章重复粘贴相同图片时复用已有资源，不重复占用空间。

### 4.3 API

#### `POST /api/editor/assets`

- 仅博客所有者可调用；
- 使用 `multipart/form-data`；
- 参数：`postId`、`file`；
- 校验文章归属、MIME、扩展名、文件头和大小；
- 写入 R2 后写入 D1 元数据；
- 返回 `assetId`、`url`、`width`（可读取时）和规范文件名。

如果 D1 写入失败，删除刚写入的 R2 对象；如果 R2 写入失败，不写 D1。

#### `GET /media/[id]/[name]`

- 读取 D1 元数据，再从 R2 返回字节；
- `published` 图片公开访问并使用长期缓存；
- `draft` 图片只允许博客所有者访问，使用 `private, no-store`；
- 设置准确 `Content-Type`、`Content-Length`、ETag 与 `X-Content-Type-Options: nosniff`；
- 文件名只用于可读 URL，真实查找以不可猜测的 asset id 为准。

### 4.4 发布可见性

发布服务从所有 Markdown 模块提取本站图片 asset id：

1. 校验图片存在且属于当前文章；
2. 在发布成功的同一业务操作中将引用图片标记为 `published`；
3. 发布快照保留稳定的 `/media/... ` URL；
4. 草稿后来删除图片引用，不影响已发布快照中的图片。

发布失败时不改变图片可见性。

## 5. 安全和限制

第一版支持 PNG、JPEG、WebP、GIF，单张最大 10MB。拒绝 SVG、HTML、PDF 和无法识别的文件头，避免脚本内容与伪造 MIME。

上传接口同时执行：

- 所有者认证；
- 每次请求一张图片；
- 服务器端大小限制；
- 文件名清洗；
- 随机对象键；
- 内容类型白名单；
- 文章存在性校验。

Markdown 渲染不允许原始 HTML。图片替代文字允许编辑，发布前不强制非空，但编辑器显示可访问性提示。

## 6. 旧文章兼容迁移

迁移发生在文章读取规范化阶段，并在下一次保存时持久化：

- `long_text`、`short_text`：原 `content` 原样成为 Markdown。
- `checklist`：`items` 转为 `- [ ] ...`；原有 Markdown `content` 若存在则置于清单前。
- `relation`：`relationSlugs` 转为 `[[slug]]`；原有 `content` 保留。
- `markdown`：原样保留。
- `standardKey`、标题、顺序和模板身份全部保留。

“阅读总结”仍通过 `standardKey === "reading-summary"` 识别；不会依赖标题或 Markdown 文本猜测，因此发布校验不会回归。

旧的常用模块模板保留标题、顺序和标准身份，但新建出来的模块统一为 Markdown。

## 7. Markdown 导入导出

### 导入

- YAML frontmatter 继续映射文章级字段。
- 每个 `##` 二级标题继续生成一个 Markdown 模块。
- GFM 清单、LaTeX、代码、表格和远程图片 URL 原样保留。
- `[[slug]]` 解析为派生关联索引。
- 本地相对图片路径无法由单个 `.md` 文件自动读取；导入时保留文本并给出明确警告。后续可增加“Markdown + 附件文件夹”批量导入，不属于本次范围。

### 导出

- 所有模块统一输出 `## 标题 + Markdown 正文`。
- 本站上传图片输出稳定的 `/media/... ` 链接。
- LaTeX、任务清单和文章关联语法保持原样。
- 不输出上传中的临时状态。

## 8. 自动保存与错误处理

图片上传与正文自动保存是两个独立状态机：

- 图片未完成上传时，不向草稿写入临时 URL。
- 上传成功后插入 Markdown，并使用已有单飞/排队自动保存机制。
- 切换文章、创建文章、导入或发布前继续调用 `flushAutosave()`。
- 发布会等待当前文章的图片上传完成；存在失败上传时阻止发布并定位到对应模块。
- 网络中断时，正文继续进入浏览器恢复副本；尚未上传的图片只保留在当前页面，刷新前提示用户重试或移除。

错误提示必须显示在对应模块旁，同时在工作台顶部汇总。不得只写入 Console。

## 9. 清理策略

为避免误删已发布文章图片：

- 不在用户删除 Markdown 链接时立即删除 R2 对象；
- 已发布图片永久保留，除非未来提供明确的资源管理器与删除确认；
- 从未发布且 30 天没有引用的 draft 图片属于可清理对象；
- 本次只实现“可识别孤儿”的查询与测试，不实现自动定时删除。

## 10. 验证标准

### 单元与集成测试

- 所有新模块创建为 Markdown。
- 旧长文本、清单、关联模块无损迁移。
- 阅读总结身份迁移后仍可发布。
- Markdown 导入导出保留 LaTeX、任务清单、关联和图片 URL。
- 图片上传校验格式、大小、文件头、归属与重复检测。
- R2 成功/D1 失败时回滚对象。
- 草稿图片不可公开，发布后可公开。
- 删除阅读总结仍阻止论文发布。
- 图片上传完成后自动保存使用最新 `draftVersion`。
- 切换文章期间上传结果不会插入另一篇文章。

### 浏览器验证

- 桌面、平板和手机可通过粘贴与文件选择插入图片。
- 上传中、成功、失败和重试状态可见。
- Markdown、图片和 LaTeX 在预览与发布文章中一致。
- 刷新后内容与图片仍存在。
- 键盘操作、焦点恢复和 44px 触摸目标符合现有要求。
