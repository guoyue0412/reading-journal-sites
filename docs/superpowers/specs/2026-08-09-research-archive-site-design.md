# 郭跃个人网站“研究档案馆”设计规格

日期：2026-08-09

状态：用户已确认，可进入实施计划

适用项目：Guo Yue Reading Journal Sites

## 1. 背景与目标

网站同时服务三个受众：站主本人、具身智能研究者和招聘方。访客进入网站后，应优先理解郭跃正在研究什么、做过什么项目、贡献是什么，以及有哪些可验证成果；论文阅读、秋招、实习和个人随笔随后展开。

本次改造采用 C“研究档案馆”路线：以研究与项目为首页核心，以学术出版物式排版组织论文和文章，同时保留个人写作的温度。网站不是通用作品集模板，也不是纯招聘落地页。

成功标准：

- 首页首屏和第一个完整内容区即可说明研究身份、当前研究问题和精选项目。
- 项目展示研究问题、个人贡献与证据，而不是只有宣传语。
- 论文、秋招、实习和随笔保持独立内容边界，并通过统一索引互相引用。
- 手机、平板和电脑均可通过网页完成新建、编辑、上传图片、预览和发布。
- 保留现有 Markdown、LaTeX、图片、结构化组件、自动保存和发布数据链路。

## 2. 调研结论与技术决策

本设计借鉴以下成熟开源方案，但不迁移技术栈：

- al-folio：借鉴论文条目、项目页、引用和研究者身份表达。
- HugoBlox Academic CV：借鉴研究履历、项目、论文与 Markdown 内容组织。
- Academic Portfolio Astro：借鉴研究内容集合、模块开关和响应式学术阅读布局。
- Academic Pages：借鉴招聘方熟悉的身份、论文、履历和联系方式入口。

保留现有 Next.js/Sites 架构。Hugo、Jekyll 或 Astro 的整体迁移会破坏现有 D1 草稿、R2 图片、网页编辑器、自动保存和发布流程，收益不足以覆盖迁移成本。

本轮不改变：

- 文章 URL 与现有路由契约。
- Markdown/frontmatter 内容格式。
- 结构化组件类型与发布校验。
- 图片上传、粘贴和 R2 地址。
- LaTeX/KaTeX 渲染。
- 自动保存版本号、冲突保护和发布接口。

## 3. 设计原则

1. 研究优先：研究问题、项目贡献和证据先于博客分类。
2. 内容优先：使用字号、层级、留白和细分隔线建立结构，不依赖装饰卡片。
3. 证据优先：项目和研究条目必须能指向论文、代码、实验、视频或阶段总结。
4. 模块隔离：论文、秋招、实习、随笔独立维护，共享搜索、主题和关联索引。
5. 同源编辑：不同设备访问同一网页编辑器，以服务器草稿作为唯一来源。
6. 克制动效：动效只服务状态反馈和方位感，不制造持续视觉噪声。

## 4. 视觉系统

### 4.1 字体

- 展示标题与随笔标题：Newsreader；中文回退为 Noto Serif SC、Songti SC。
- 正文与界面：IBM Plex Sans；中文回退为 Noto Sans SC、PingFang SC。
- Markdown、代码和技术数据：IBM Plex Mono；回退为 SFMono-Regular。

字号基线：

- 首页主标题：桌面端 64–80px，移动端 40–48px。
- 页面标题：桌面端 44–56px，移动端 34–40px。
- 正文：17px，行高 1.7，推荐阅读宽度约 65ch。
- 导航与界面：14–15px。
- 元数据：12–13px。

个人随笔通过衬线标题、更宽松的行距和段落间距获得随笔感；论文、项目、秋招和编辑器使用更紧凑的现代编辑密度。不新增第四套字体。

### 4.2 色彩

颜色使用 OKLCH 设计令牌：

```css
--paper: oklch(97% 0.012 85);
--paper-soft: oklch(94% 0.014 85);
--ink: oklch(22% 0.018 255);
--ink-muted: oklch(49% 0.018 255);
--rule: oklch(84% 0.015 85);
--accent: oklch(43% 0.12 28);
--focus: oklch(57% 0.16 28);
```

暖象牙白用于页面背景，蓝黑用于正文，灰蓝用于元数据，暗朱红只用于当前研究、活动状态、关键链接和焦点。强调色不超过主要视口面积的约 3%。不使用纯黑、纯白、大面积渐变、环境光球或玻璃模糊。

### 4.3 空间与边界

- 公共内容最大宽度约 1180px，文章正文约 65ch。
- 组件通过 1px 细线和留白分区。
- 公共阅读面不使用悬浮阴影和卡片上浮。
- 仅在编辑器面板等确有语义容器的场景使用 4–6px 小圆角。
- 触控目标不小于 44px。

## 5. 信息架构

首页顺序固定为：

1. 研究身份。
2. 当前研究问题。
3. 精选研究项目。
4. 研究主题。
5. 最近论文阅读。
6. 秋招、实习和个人随笔。
7. 完整内容索引。

全站导航：

```text
郭跃    研究 / 项目 / 论文 / 记录 / 关于           搜索 / 编辑
```

“编辑”是站主工具，视觉上弱于研究导航，但始终可发现。`/editor` 可直接收藏和访问。

统一索引支持关键词、内容类型、标签、主题、时间和 `related` 关系。模块各自保存和展示，不把论文进度、秋招阶段和随笔日期压缩成一个通用状态模型。

## 6. 页面与组件

### 6.1 全局导航

导航采用学术期刊刊头结构：站名与研究身份明确，主导航独立成行或保持清晰间距，并用细线建立秩序。当前页面使用文字颜色和短下划线标记。手机端使用可访问的折叠菜单，不使用悬浮玻璃导航。

### 6.2 首页

首页首屏采用非对称编辑排版：

- 左侧：姓名、具身智能研究方向、一句话研究主张，以及 GitHub、简历和联系方式。
- 右侧：当前研究问题、简短判断和更新时间，用一条暗朱红竖线标记。
- 首屏之后立即展示精选研究项目。

项目不再使用三个等宽悬浮卡片，而采用纵向研究证据条目。最近论文和最近记录可在宽屏上形成两列，但不放进装饰容器。移动端按身份、当前问题、项目、论文、记录顺序转为单列。

### 6.3 项目页

每个项目包含：

1. 研究问题。
2. 方法与架构。
3. 我的贡献。
4. 证据与产物。

证据可以关联论文、论文笔记、代码仓库、实验结果、图表、演示视频和阶段总结。项目列表默认显示研究问题和贡献，不只显示项目名与一句宣传语。

### 6.4 论文索引

桌面端采用紧凑文献表：日期、阅读方式、执行状态、论文标题、来源和研究主题形成稳定列。移动端改为纵向条目，不缩小文字模拟桌面表格。

筛选支持：

- 关键词。
- 研究主题。
- 阅读方式多选：粗读、细读、总结。
- 执行状态单选：待读、阅读中、总结中、已完成、已归档。
- 时间排序。

阅读方式和执行状态使用现有结构化数据，不从 Markdown 标题猜测。论文不强制拥有全部阅读阶段。

### 6.5 文章页

文章头部保留内容类型、标题、摘要、日期、更新时间、标签、阅读方式、状态和关联内容。正文约 65ch。桌面端目录位于右侧，手机端折叠到文章头部。

图片可以突破正文列但不能突破页面内容网格；LaTeX、代码块和宽表格只在自身容器中横向滚动。Markdown 或公式解析失败时显示可读源内容和明确错误，不让整个页面崩溃。

### 6.6 秋招页

采用纵向进展账本：公司、岗位以及投递、笔试、面试、结果。每个实际发生的阶段可以记录日期、状态、材料和复盘；未发生阶段不创建空卡片。

### 6.7 个人随笔

随笔使用更大的衬线标题、独立日期、更宽松的段落间距。隐藏无关的结构化工具信息，底部提供上一篇、下一篇和同日关联内容。

### 6.8 编辑器

编辑器保持结构化模块与 Markdown 文本框并存：

- 每个模块提供独立 Markdown 输入。
- 支持添加任意新组件。
- 支持保存为常用模块。
- 支持本地图片上传和粘贴。
- 支持图片、表格、代码和 LaTeX 实时预览。
- 支持 Markdown 双向导入导出。
- 显示自动保存、冲突和发布状态。
- 发布失败直接显示后端返回的 `error` 与 `fields`。

视觉上使用暖白画布、细分隔线、IBM Plex Sans 界面字体和 IBM Plex Mono 输入字体。不使用模糊、发光和大阴影。

## 7. 跨设备网页编辑

不建设 PWA、离线编辑或独立应用。手机、平板和电脑均通过同一网址访问，`/editor` 可直接收藏。手机浏览器可以使用系统提供的“添加到主屏幕”，但网站不引入复杂缓存。

### 7.1 电脑端

三栏布局：文章列表、模块与 Markdown 编辑、实时预览。工具栏提供保存状态、导入、导出、预览和发布。

### 7.2 平板端

文章列表放入侧边抽屉。横屏显示编辑和预览双区；竖屏允许编辑与预览切换。工具栏吸顶且适合触控。

### 7.3 手机端

使用单列编辑流：文章信息、模块列表、当前 Markdown 文本框、媒体与公式预览、底部固定操作栏。底部只保留添加模块、预览、保存状态和发布；排序、删除和保存为常用模块位于模块菜单。

输入框获得焦点时，底部操作栏不得遮挡文字或系统键盘。长公式、代码和宽表格只在自己的容器内滚动。

## 8. 数据流与错误处理

服务器草稿是跨设备唯一来源：

```text
编辑器状态
→ 自动保存请求
→ 服务器草稿与版本号
→ 重新读取
→ 发布接口读取
→ 发布校验
```

- 自动保存继续使用版本号和单飞请求避免覆盖。
- 切换文章、新建、导入、另存或发布前完成待保存内容。
- 网络中断时保留当前输入并显示“等待重新保存”。
- 版本冲突不得静默覆盖，提供重新载入和保留本地文本的明确选择。
- 图片上传完成前不把临时地址写入文章。
- 登录失效时返回登录页，成功后回到原编辑文章。
- 发布失败在操作区展示后端 `error` 和 `fields`，不只记录通用 400 错误。

## 9. 动效与可访问性

- 页面载入最多使用一次 160–220ms 的透明度与轻微位移动画。
- 列表悬停只改变文字颜色或下划线，不上浮。
- 编辑器状态变化只使用功能性过渡。
- `prefers-reduced-motion` 下移除位移并将动画控制在 150ms 内。
- 所有交互提供默认、悬停、键盘焦点、按下、禁用、加载、错误和成功状态。
- 保持语义标题顺序、可见标签、键盘导航和足够的颜色对比度。

## 10. 验收与回归范围

视口：

- 320px 小屏手机。
- 375px 常用手机。
- 414px 大屏手机。
- 768px 平板竖屏。
- 1024px 平板横屏。
- 1440px 桌面端。

公共页面验收：

- 首页优先展示研究身份、当前问题和项目证据。
- 导航、项目、论文、文章、秋招、随笔和索引风格一致。
- 页面没有整体横向滚动。
- 图片保持比例，LaTeX、代码和表格可读。
- 键盘焦点清楚，减少动态效果设置有效。

编辑验收：

- 手机、平板和电脑均可新建、编辑、预览和发布。
- 本地图片上传与粘贴成功，刷新后仍然存在。
- LaTeX 即时渲染，解析失败保留可读源内容。
- 模块可以创建、编辑、排序、删除并保存为常用模块。
- Markdown 导入导出不丢失模块、图片或公式。
- 自动保存后刷新不丢失内容。
- 切换文章或设备不会把草稿写入错误文章。
- 发布错误完整显示后端错误字段。
- 现有完整测试和生产构建通过。

## 11. 实施边界与顺序

第一阶段实施：

1. 建立统一设计令牌、字体、页面网格和交互状态。
2. 重构导航、首页和项目证据条目，形成最小视觉切片。
3. 改造项目、论文索引、文章、秋招、实习、随笔和统一索引。
4. 改造编辑器在桌面、平板和手机上的布局与状态反馈。
5. 完成响应式、可访问性、数据链路回归和生产构建验证。
6. 验证通过后重新发布。

明确延后：

- BibTeX 自动导入。
- PWA 与离线编辑。
- 暗色模式。
- 新动画库。
- 数据库和发布协议重写。
- Hugo、Jekyll 或 Astro 迁移。
